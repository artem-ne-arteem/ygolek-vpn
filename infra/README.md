# Поднятие VPN-ноды

Пошагово: от пустого VPS до работающего ключа в боте и на сайте.

## 1. Арендовать VPS

Нужен провайдер с дата-центром за пределами РФ —
например Hetzner, Contabo, DigitalOcean или Aeza (в локации вне РФ, например
Хельсинки). Минимальные требования:

- Ubuntu 22.04+
- **2 vCPU / 4 GB RAM** — на 1-2 GB Docker-образы Marzban при установке
  упираются в память (проверено на практике)
- root-доступ по SSH

## 2. Настроить DNS — ДО запуска скрипта

DNS сайта и доменов ведётся через **Vercel** (не через регистратора reg.ru —
управление перенесено туда при подключении доменов к сайту). Добавь A-запись
поддомена на IP сервера через дашборд/CLI Vercel:

```
sub.ygolek-vpn.online  A  <IP сервера>
```

Именно этот поддомен пойдёт в `MARZBAN_SUB_DOMAIN` и в него же будет выпущен
HTTPS-сертификат — **скрипт не сработает, пока DNS не указывает на сервер**
(Let's Encrypt проверяет владение доменом по HTTP).

## 3. Запустить установочный скрипт

```bash
scp setup-marzban.sh root@<IP сервера>:~/
ssh root@<IP сервера>
bash setup-marzban.sh sub.ygolek-vpn.online admin@ygolek-vpn.online
```

Скрипт ставит Docker, Marzban, выпускает Let's Encrypt сертификат на
поддомен и настраивает Marzban на HTTPS напрямую (без внешнего
reverse-proxy — так порт 443 остаётся свободным под сам VLESS+Reality
inbound, а панель работает на 8000 через HTTPS), открывает порты
80/443/8000 в файрволе и просит создать первого админа панели.

**Почему через сертификат, а не просто IP:порт по HTTP:** начиная с
определённой версии Marzban сам отказывается слушать что-либо, кроме
localhost, пока не заданы SSL-сертификаты — иначе dashboard и
subscription-ссылки просто не были бы доступны снаружи. Подробности и сам
механизм — в комментариях `setup-marzban.sh`.

## 4. Настроить VLESS+Reality inbound

Зайди в `https://<поддомен>:8000/dashboard/`, залогинься под созданным
админом и добавь inbound:

- протокол: **VLESS**
- сеть: **TCP**, security: **Reality**
- порт: **443**
- имя inbound-а: **`VLESS TCP REALITY`** (важно — под этим именем его ищут
  `bot/bot/marzban/client.py` и `site/lib/marzban.ts` при создании
  пользователей)

Marzban сам генерирует Reality-ключи в UI при создании inbound-а — руками
ничего считать не нужно.

## 5. Подключить бота и сайт к ноде

В `bot/.env`:

```
MARZBAN_MOCK=false
MARZBAN_API_URL=https://sub.ygolek-vpn.online:8000
MARZBAN_ADMIN_USERNAME=<логин из шага 3>
MARZBAN_ADMIN_PASSWORD=<пароль из шага 3>
MARZBAN_SUB_DOMAIN=sub.ygolek-vpn.online
```

Те же четыре переменные — в env сайта на Vercel (`vercel env add ... production,preview,development`, значения совпадают).

Перезапусти бота и передеплой сайт (`vercel --prod`) — теперь и `/start` →
пробный период / покупка тарифа в боте, и личный кабинет на сайте создают
реального пользователя в Marzban и отдают рабочую subscription-ссылку,
которая открывается в Happ / v2rayNG / v2RayTun.

## Масштабирование на несколько нод

Когда одной ноды станет мало — MVP держит один `MARZBAN_API_URL` в конфиге
бота и сайта. Следующий шаг (вне рамок этой итерации): вынести список нод в
БД и выбирать ближайшую/наименее загруженную при выдаче ключа.
